一次仿冒Chrome钓鱼站的分析与溯源：从死循环到Whois线索

2026-09-13 admin SRC

从仿冒 Chrome 钓鱼站到 Whois 溯源：一次脱敏后的安全分析记录

前言

前几天在浏览网页时，偶然发现了一个高仿 Google Chrome 下载页面的网站：

https://zh.google-google-google-cn.example.cn

域名里重复出现的 google-google-google-cn 和 example.cn 后缀立刻引起了我的注意。经过一番分析，我发现这不仅是一个简单的钓鱼站，背后还隐藏着一条完整的黑色产业链，而且这个钓鱼站本身还存在一个致命的 Bug——它把自己卡死了。

这篇文章记录了整个分析过程，包括域名解析、Whois 溯源、跳转链分析以及最终发现的“死循环”现象。希望能给其他安全研究者提供一些参考。本文已对真实域名、注册人、邮箱、注册商、编号、时间等信息进行脱敏处理。

一、初步观察：域名与页面

打开链接后，页面几乎完美复刻了 Google Chrome 的官方下载页，包括 Chrome 的 Logo、版本号、下载按钮等。但仔细看域名，就会发现明显异常：

  • 真正的 Google 域名应该是 google.com 或 google.cn；
  • 而这个域名是 zh.google-google-google-cn.example.cn，其中 example.cn 是一个完全无关的域名，前面堆砌了多个 google 字样，明显是为了迷惑用户。

我意识到，这是一个典型的仿冒品牌钓鱼站，目的是诱导用户下载捆绑了恶意软件的“Chrome 安装包”。

二、Whois 溯源：实名注册的线索

对域名 google-google-google-cn.example.cn 进行 Whois 查询，得到了非常关键的信息：

Domain Name: google-google-google-cn.example.cn
ROID: 已隐去
Domain Status: ok
Registrant: 某注册人（已脱敏）
Registrant Contact Email: user@example.com
Sponsoring Registrar: 某域名注册商（已脱敏）
Name Server: ns1.example-registrar.example
Name Server: ns2.example-registrar.example
Registration Time: 近期某日
Expiration Time: 约一年后
DNSSEC: unsigned

几个关键点：

  1. 注册信息未做隐私保护：注册人和邮箱信息可被查询到（本文已脱敏）。这在黑产中比较少见，可能是疏忽或身份冒用，但无论如何，这是一个重要的溯源线索。
  2. 注册时间很近：域名注册于近期，距离我发现它仅一个月左右，说明攻击者正在积极更新基础设施。
  3. 注册商可举报：我们可以向该域名注册商举报域名用于钓鱼，要求暂停解析。
  4. 主域名 example.cn：该主域名下还有大量类似子域名，如 doubao.example.cn、apps-google-qq.example.cn 等，说明这是一个专门用于钓鱼的域名集群。

三、跳转链与死循环：黑产自己玩脱了

为了进一步分析，我模拟了普通用户的点击行为。点击“下载 Chrome”按钮后，页面并没有直接下载文件，而是经历了一连串跳转：

仿冒页 → 下载站 → 假安全检查页 → 仿冒页 → ...

无论我如何更换网络（切换 WiFi、使用手机流量），这个循环都会稳定复现。也就是说，恶意软件分发流程卡死了。

经过分析，我认为原因如下：

  1. 代码拼凑冲突：该钓鱼站可能同时套用了电脑版、手机版等多套诈骗模板，模板之间逻辑冲突，导致跳转判断出错。
  2. 风控系统误判：黑产通常会在页面中加入风控系统，试图筛选掉安全研究人员、虚拟机 IP 等。但风控逻辑可能与跳转逻辑互相干扰，造成了死锁。
  3. 远程脚本不稳定：跳转依赖远程服务器返回的指令，如果服务器端脚本存在 Bug，也会导致循环。

这个死循环对我来说是个好消息——它意味着恶意软件没有成功下发，我没有中招。但同时，这也说明该攻击系统仍然在运行，只是不稳定；未来某个时刻，某次请求可能就会突然“成功”，把木马真正下载到用户电脑上。

四、危害分析

尽管我这次没有中招，但这个钓鱼站的潜在危害依然很大：

  • 恶意软件分发：下载的“Chrome 安装包”很可能捆绑了远控木马、信息窃取软件或挖矿病毒。
  • 品牌仿冒：利用 Google Chrome 的知名度降低用户警惕，尤其是对普通网民来说，很难分辨域名真伪。
  • SEO 投毒：攻击者可能通过搜索引擎优化，让这个页面出现在“Chrome 下载”等关键词的搜索结果中，扩大影响面。
  • 黑产基础设施：example.cn 下还有多个同类子域名，说明这是一个有组织的黑产团伙，可能同时运营着多个钓鱼项目。

五、合规上报与处置建议

作为安全研究者，我在分析过程中始终坚持“只观察、不交互”的原则，没有下载任何文件，也没有进行任何破坏性操作。

目前，我已经整理了以下线索，准备向相关平台提交：

  • 域名：zh.google-google-google-cn.example.cn
  • Whois 信息：注册人、邮箱、注册商等（均已脱敏）
  • 异常行为：PC 端与移动端均复现“仿冒页→下载站→假安全检查页→仿冒页”的死循环
  • 潜在危害：仿冒 Chrome 分发恶意软件，且攻击框架存在不稳定特征

提交渠道：

  1. 国内漏洞响应平台：作为恶意 URL/信息泄露类漏洞提交，争取现金奖励。
  2. 国家互联网应急中心（CNCERT）：上报钓鱼网站，协助关停。
  3. 域名注册商：向该域名注册商举报，要求暂停域名解析。
  4. Google 官方：通过 Google 的钓鱼网站举报渠道提交。

六、个人感悟

这是我第二次独立分析网络安全事件。第一次是从某视频平台内链跳转漏洞一路追到被篡改的政府网站，那次让我学会了“溯源思维”；这一次则是从仿冒 Chrome 钓鱼站入手，学会了 Whois 查询、跳转链分析和死循环判定。

虽然这个钓鱼站因为自身的 Bug 没有真正得逞，但分析过程让我对黑产的运作方式有了更直观的认识。更重要的是，我意识到：安全研究不一定要“攻破”什么，有时候，观察、记录、上报，本身就是一种力量。

希望这篇文章能对刚入门的安全研究者有所帮助。如果你也发现了类似的钓鱼站，记得：不要下载任何文件，不要输入任何信息，保留证据，合规上报。
